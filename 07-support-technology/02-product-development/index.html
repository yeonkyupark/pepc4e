    7.2.1 신제품 개발 프로세스¶

    개요: 신제품 개발은 기업 성장과 경쟁력의 원천이지만, 많은 아이디어 중 소수만 상업적으로 성공하므로(아이디어 깔때기) 단계별 선별과 위험 관리가 핵심이다. 또한 제품 원가·품질의 대부분이 개발·설계 단계에서 결정되므로 공장관리 관점에서도 설계 단계의 관리가 중요하다.

    신제품 개발 과정 (68·100·109회)¶

    flowchart LR
    A["① 아이디어 창출"] --> B["② 아이디어 선별"] --> C["③ 제품 개념 개발·<br/>타당성 검토"] --> D["④ 예비 설계"] --> E["⑤ 최종(세부) 설계"] --> F["⑥ 시제품·시험"] --> G["⑦ 시험 마케팅"] --> H["⑧ 상업화(양산·출시)"]
    단계 주요 내용
    아이디어 창출 고객 요구(VOC), 연구개발, 경쟁사, 영업·현장 제안에서 아이디어 수집
    아이디어 선별 전략 적합성·시장성·실현 가능성으로 걸러냄
    개념 개발·타당성 제품 개념 정의, 시장성·기술성·경제성 검토
    예비 설계 대안 개념 비교, 핵심 기능·구조 결정
    최종 설계 상세 사양·도면 확정 — 아래 세부 과정
    시제품·시험 성능·신뢰성 시험, 설계 검증·유효성 확인
    시험 마케팅 일부 시장에서 반응 확인
    상업화 양산 준비, 출시

    최종 설계의 세부 과정 (109·130회): ① 기능 설계(성능·신뢰성·보전성 등 기능 요구를 충족) → ② 형태 설계(외관·형상·크기·색상 등 사용자 관점) → ③ 생산 설계(제조 용이성, 표준 부품, 공차, 원가) → 시제품 시험 → 설계 확정

    예비 설계와 최종 설계 (130회): 예비 설계는 여러 개념 대안 중 최선안을 고르고 기본 구조를 정하는 단계이고, 최종 설계는 선택된 안을 상세 사양·도면·공차까지 확정해 생산할 수 있게 만드는 단계다. 제품수명주기(PLC)는 1.5.2를 참고한다.

    단계-관문(Stage-Gate) 관리: R. G. Cooper가 체계화한 방식으로, 각 단계 끝에 관문(Gate) 심사를 두어 진행(Go)·중단(Kill)·보류(Hold)·재작업(Recycle)을 결정해 개발 위험과 자원 낭비를 관리한다.

    flowchart LR
    G1{"관문1<br/>아이디어 심사"} --> S1["단계1<br/>범위 설정"] --> G2{"관문2"} --> S2["단계2<br/>사업성 검토"] --> G3{"관문3<br/>개발 승인"} --> S3["단계3<br/>개발"] --> G4{"관문4"} --> S4["단계4<br/>시험·검증"] --> G5{"관문5<br/>양산 승인"} --> S5["단계5<br/>출시"]

    신제품 개발의 성공 요인과 최근 동향

    구분 내용
    성공 요인 명확한 제품 정의(고객 가치), 초기 단계의 철저한 사전 검토, 부서 횡단팀·동시공학, 관문 심사의 엄격한 운영, 경영층 지원
    실패 요인 시장 조사 부족, 기술 과신, 개발 지연, 원가 초과, 출시 시기 실패
    최근 동향 가상 개발(CAE·디지털 트윈으로 시제품 축소), AI·생성형 설계, 애자일 개발(짧은 반복 주기), 오픈 이노베이션, 친환경 설계·디지털 제품 여권 대응(7.5.1)

    고객 요구 파악 기법 (65회)¶

    ① 설문조사(정량적으로 다수 고객의 의견 수집) ② 포커스 그룹 인터뷰(FGI)(소수 고객과 심층 토론) ③ 관찰·에스노그래피(실제 사용 환경 관찰로 숨은 요구 발견) — 이 밖에 심층 면접, 클레임·VOC 분석, 컨조인트 분석

    기타 개념¶

    • MGPP & TD (65회): 다세대 제품 계획(MGPP)은 제품을 여러 세대에 걸쳐 기능을 진화시키는 장기 로드맵이고, 선행 기술 개발(TD)은 제품 개발에 앞서 필요한 기술을 미리 확보하는 활동이다. 목적: 장기적인 제품 경쟁력의 지속, 세대별 출시 시기와 자원의 계획적 배분, 제품 개발 단계의 기술 위험·개발 기간 감소
    • R&BD (79회): 연구개발 단계부터 시장과 사업화를 염두에 두고 기술 개발 → 제품화 → 사업화까지 연계하는 연구개발(Research & Business Development)
    • 신제품 개발의 마케팅 전략 (73회): 시장 세분화·표적시장·포지셔닝(STP) → 제품 컨셉 → 가격·유통·촉진(4P) → 시험 마케팅 → 출시 시기 전략(선발자·후발자)
    • 제품 디자인에 활용되는 기법 (91회): QFD, 동시공학, DFM·DFA, 모듈러 설계, VE, 강건 설계, FMEA, CAD·CAE

    답안 작성 포인트

    • 신제품 개발 과정은 단계 흐름도 + 단계별 내용 표로 쓴다. 문제가 설계 과정을 강조하면 예비 설계 / 최종 설계(기능·형태·생산 설계)를 자세히 쓴다.
    • Stage-Gate 그림과 단계별 활용 기법(QFD → DFM → FMEA → DR)을 연결하면 차별화된다.
    • 결론 예: "개발 초기의 결정이 원가·품질의 대부분을 좌우하므로, 관문 심사와 동시공학으로 앞 단계에서 문제를 해결하고 PLM·디지털 트윈 기반 가상 개발로 개발 기간을 단축해야 한다."

    7.2.2 품질기능전개(QFD·HOQ)¶

    품질기능전개(QFD) (65·70·85회)¶

    정의: 고객의 요구(VOC)를 제품의 기술 특성(설계 품질)으로 바꾸고, 이를 부품 특성 → 공정 조건 → 생산 계획까지 단계적으로 전개하는 품질 설계 기법이다(아카오 요지, 일본).

    4단계 전개: ① 제품 계획(품질의 집, HOQ) → ② 부품 전개 → ③ 공정 계획 → ④ 생산 계획

    효과: 고객 요구에 맞는 제품 개발, 설계 변경·개발 기간 감소, 부서 간 의사소통 향상, 개발 지식의 축적

    배경: 1960년대 후반 일본에서 아카오 요지·미즈노 시게루 등이 개념을 제시했고, 1970년대 초 미쓰비시 중공업 고베 조선소의 품질표 활용을 거쳐 도요타 등으로 확산되었다(1980년대 미국 도입).

    flowchart LR
    V["고객 요구<br/>(VOC)"] --> H1["① 제품 계획<br/>HOQ"] -->|기술 특성| H2["② 부품 전개"] -->|부품 특성| H3["③ 공정 계획"] -->|공정 조건| H4["④ 생산 계획<br/>작업 표준·관리"]

    한계와 보완: 행렬이 커지면 작성 부담이 크고, 고객 요구의 정성적 판단에 의존한다 → 핵심 요구에 집중, 카노 모델(5.4.7)로 요구를 분류해 중요도 보정, AHP로 중요도 산정, 최근에는 리뷰·VOC 텍스트를 AI로 분석해 고객 요구를 추출한다.

    2. 요구 품질 전개표 작성: 원시 VOC를 요구 품질로 바꾸고 친화도법으로 1차 → 2차 → 3차 항목으로 계층화

    4. 기획 품질 설정: 자사·경쟁사 비교, 목표 수준·개선율·세일즈 포인트 결정
    5. 품질 특성 전개: 요구 품질을 측정 가능한 품질 특성으로 변환하고 관계 행렬 작성

    • 사례 표에는 기술 중요도 계산(관계 점수 × 요구 중요도의 합)과 지붕의 상충 관계 해석을 반드시 넣는다 — 계산과 해석이 있어야 고득점이다.
    • 결론 예: "QFD는 고객의 언어를 기술·공정의 언어로 바꾸는 부서 간 공통 언어이므로, 동시공학 팀의 도구로 쓰고 카노 모델·VOC 빅데이터 분석으로 보완해야 한다."

    7.2.3 동시공학(CE)¶

    동시공학(CE)과 순차공학(SE) (94·124회)¶

    동시공학(Concurrent Engineering)은 제품 개발 초기부터 설계·생산기술·품질·구매·마케팅·협력사가 부서 횡단팀으로 동시에 참여해, 제품과 공정을 병행 설계하는 개발 방식이다.

    구분 순차공학(SE) 동시공학(CE)
    진행 방식 기획 → 설계 → 생산기술 → 생산을 차례로 넘김("담장 너머로 던지기") 여러 단계를 겹쳐서 병행
    조직 기능 부서별 부서 횡단팀(CFT)
    설계 변경 후반에 문제가 드러나 변경이 많음 초기에 문제를 반영해 변경 감소
    개발 기간·비용 길고 큼 짧고 작음
    정보 공유 단계 끝에 일괄 전달 실시간 공유(PDM·PLM)

    배경: 1980년대 미국 제조업이 일본 기업보다 개발 기간이 길고 설계 변경이 많다는 반성에서 확산되었으며, 1988년 미국 국방분석연구소(IDA) 보고서가 "제품과 관련 공정(제조·지원)을 통합·동시에 설계하는 체계적 접근"으로 정의한 것이 널리 인용된다.

    도입 시 문제점과 대응: 부서 간 갈등·책임 불명확 → 프로젝트 관리자(중량급 PM)에게 권한 부여 / 미확정 정보로 인한 재작업 → 정보의 단계적 공개와 빈번한 소통 / 정보 시스템 투자 부담 → PLM 단계적 구축

    최근 동향: PLM 기반의 디지털 동시공학 — 3D 모델 기반 정의(MBD), CAE·가상 시운전, 협력사와의 클라우드 협업, 디지털 스레드(7.5.2)로 설계–제조–보전 데이터 연결

    동시공학의 구성 요소와 효과를 얻기 위한 요소 (73·100회)¶

    1. 부서 횡단팀(CFT)과 강한 프로젝트 관리
    2. 정보 공유 체계: CAD·CAE, PDM·PLM, 공용 데이터베이스
    3. 설계 도구: QFD, DFM·DFA, FMEA, 강건 설계
    4. 공급자 조기 참여(ESI)
    5. 경영층의 지원과 협업 조직 문화, 개발 프로세스의 표준화

    7.2.4 제조용이성 설계(DFM)와 원가지향 설계¶

    제조용이성 설계(DFM) (82·94·124회)¶

    표준·공용 부품 표준 체결 부품, 기존 부품 재사용
    모듈화 하위 조립 단위로 분리해 병렬 조립

    공차 적정화 공정 능력에 맞는 공차(과잉 정밀도 배제)

    실수방지 설계 잘못 조립할 수 없는 비대칭 형상

    방법론: Boothroyd-Dewhurst의 DFA 조립 효율 지수, 설계 검토(DR), 동시공학 팀, CAD 기반 제조성 분석 — 서비스성·환경까지 확장한 개념을 DFX라 한다.

    [그림] 설계 단계의 원가 결정과 변경 비용: 제품 원가의 약 70~80%가 설계 단계에서 결정된다고 알려져 있는 반면, 설계 단계에서 실제로 쓰는 비용은 작다. 설계 변경 비용은 단계가 늦어질수록 급격히 커지므로(흔히 "10배 법칙"이라 함) 앞 단계에서 제조성을 반영해야 한다.

    DFA 설계 효율(Boothroyd-Dewhurst)

    \[ E_{ma} = \frac{N_{min} \times t_a}{t_{ma}} \]
    • \( N_{min} \): 이론적 최소 부품 수 — 부품이 ① 다른 부품과 상대 운동을 하거나 ② 다른 재질이어야 하거나 ③ 분리되어야 조립·분해가 가능한 경우에만 독립 부품으로 인정
    • \( t_a \): 이상적인 부품 1개당 조립 시간(약 3초), \( t_{ma} \): 실제 총 조립 시간
    • 효율이 낮으면 부품 통합·체결 방식 개선의 여지가 크다.
    DFX 유형 고려 대상
    DFM / DFA 제조·가공 / 조립 용이성
    DFT(Testability) 검사·시험 용이성
    DFS(Serviceability) 정비·수리 용이성
    DFR(Reliability) 신뢰성
    DFE(Environment) 친환경·재활용·분해 용이성 — 4.3.1 참고
    DFC(Cost) 목표원가 달성

    모델 다양화로 손익이 악화된 A전자 (65회)¶

    현행 개발상의 문제점: 모델 수 증가에 따른 부품·금형·재고의 증가, 모델별 개별 설계로 부품 공용화 부족, 개발 단계의 원가 검토 부족, 설계 변경 반복과 개발 기간 장기화 → 원가 증가율(15%)이 매출 증가율(10%)을 웃돎

    개선 전략: ① 플랫폼·모듈화로 공통 부분과 차별 부분 분리 ② VRP로 부품 종류 축소·공용화 ③ 목표원가 기획과 VE ④ DFM·DFA ⑤ 동시공학과 설계 표준·재사용 체계

    답안 작성 포인트

    • 원가 절감 설계 방식은 "모두 쓰라"는 문제가 많으므로 7가지 정도를 표로 정리해 둔다.
    • 서론에 "원가의 70~80%가 설계 단계에서 결정" 그림(원가 결정 곡선 vs 발생 곡선)을 넣으면 왜 설계 단계인지가 분명해진다.
    • 결론 예: "원가는 만든 뒤 줄이는 것보다 설계에서 정하는 것이 효과적이므로, 목표원가·VE·DFM을 개발 관문 심사 항목으로 제도화해야 한다."

    7.2.5 모듈러 설계·VRP·제품 플랫폼¶

    모듈러 설계 (97·115·136회)¶

    개념: 제품을 표준화된 인터페이스를 가진 독립 기능 단위(모듈)로 나눠 설계하고, 모듈의 조합으로 다양한 제품을 만드는 설계 방식이다.

    모듈화의 목적 (136회): ① 다양한 고객 요구에 적은 원가로 대응(대량맞춤) ② 부품 공용화로 규모의 경제와 원가 절감 ③ 병렬 개발·생산으로 개발·생산 기간 단축

    관점 장점 (136회)
    Q 품질 검증된 모듈 재사용과 모듈 단위 검사로 품질 안정
    D 납기 모듈 병렬 생산·조립으로 리드타임 단축
    F 유연성 모듈 조합으로 다양한 사양에 신속 대응
    R 위험 설계 변경·고장의 영향이 해당 모듈에 국한
    C 원가 공용화·대량 생산으로 원가 절감, 재고 감소
    관점 단점 (136회)
    Q 품질 모듈 간 인터페이스 문제, 전체 최적보다 성능이 낮을 수 있음
    C 원가 모듈 표준 개발에 초기 투자, 과잉 사양으로 일부 제품 원가 상승
    기타 제품 간 차별성 약화, 경쟁사의 모방 용이, 아키텍처가 고착되어 혁신 제약

    제품 아키텍처: 모듈형 vs 통합형 (K. Ulrich)

    구분 모듈형 아키텍처 통합형 아키텍처
    기능–부품 대응 1:1에 가까움, 표준 인터페이스 여러 기능이 여러 부품에 얽힘
    강점 다양성·변경 용이, 병렬 개발, 아웃소싱 용이 성능 최적화, 소형·경량화
    예 PC, 산업용 설비 유닛 고성능 엔진, 초소형 전자기기

    모듈 유형: 슬롯형(모듈마다 인터페이스가 다름), 버스형(공통 버스에 여러 모듈 연결), 섹셔널형(동일 인터페이스로 서로 연결) — 생산 측면의 모듈 생산은 1.2.7을 참고한다.

    모듈화 추진 절차(예): ① 제품군의 고객 요구·사양 분석 → ② 기능 분해와 공통·가변 기능 구분 → ③ 모듈 경계와 표준 인터페이스 정의 → ④ 모듈 구성표(조합 규칙) 작성 → ⑤ 부품·공정 공용화와 효과 평가

    VRP(Variety Reduction Program) (85·115회)¶

    필요성: 고객 요구 다양화로 제품 종류가 늘면 부품 수·금형·재고·관리 비용이 급증한다. VRP는 제품 다양성은 유지하면서 부품·공정의 다양성을 줄이는 활동이다.

    VRP 5대 개념 내용 예
    ① 고정과 변동 변하지 않는 부분은 고정·표준화하고, 바뀌는 부분만 분리 휴대폰 본체 공통, 외장 커버만 변경
    ② 편성의 조합(모듈화) 적은 수의 모듈 조합으로 많은 제품 구성 모듈 3종 × 4종 = 12개 모델
    ③ 다기능의 집약(GT) 여러 부품의 기능을 하나로 통합, 유사 부품을 그룹화 브래킷 3개를 하나의 공용 브래킷으로
    ④ 범위(Range) 사양의 적용 범위를 넓혀 부품 종류 축소 전압 범위가 넓은 전원부 하나로 여러 국가 대응
    ⑤ 계열(Series) 크기·용량을 표준수(등비 수열)로 계열화 모터 용량을 1·2·4·8kW 계열로 정리

    제품 플랫폼 (79회)¶

    의미: 여러 파생 제품이 공유하는 공통 부품·구조·기술의 집합이다. 플랫폼을 바탕으로 짧은 기간에 다양한 제품을 만든다.

    전략 유형: 세분시장 특화, 수평적 활용, 수직적 확장(상향·하향·양방향), 교두보(Beach Head) — 자세한 내용은 1.1.5를 참고한다.

    베네통의 차별화 지연 (115회)¶

    베네통은 실을 먼저 염색한 뒤 스웨터를 짜던 공정을 바꿔, 염색하지 않은 스웨터를 먼저 짜 두고 판매 시즌에 유행 색상이 확인되면 염색했다. 제품의 차별화(색상) 시점을 늦춰 공통 반제품 단계에서 수요를 합쳐 관리하므로 예측 오차·재고·품절이 줄었다. 이를 위해 공정 순서를 바꾸고 염색 기술을 개발하는 제품·공정의 재설계가 필요했다.

    답안 작성 포인트

    • 136회처럼 관점(QDFRC)을 지정하면 그 관점을 표의 행으로 그대로 쓴다.
    • VRP 5대 개념은 개념 + 구체적 예를 함께 쓴다.
    • 모듈러 설계는 모듈형 vs 통합형 아키텍처 비교와 대량맞춤(1.1.5)·차별화 지연 연결로 깊이를 더한다.
    • 결론 예: "모듈화는 외부 다양성은 넓히고 내부 다양성은 줄이는 전략이므로, 플랫폼·VRP와 함께 추진하되 인터페이스 표준과 핵심 차별 모듈의 내재화로 단점을 보완해야 한다."

    7.2.6 DFSS와 설계 검토¶

    설계 검토·검증·유효성 확인 (63회, ISO 9001)¶

    질문 설계가 제대로 진행되고 있는가? 제대로 만들었는가?(Built it right) 올바른 것을 만들었는가?(Built the right thing)
    방법 단계별 검토 회의(관련 부서 참여) 계산 검토, 시험, 도면·사양 대조, 시제품 시험 실제 사용 조건 시험, 시범 사용, 고객 평가

    구분 DMAIC(6시그마) DFSS(DMADV)

    답안 작성 포인트

    • 설계 검토·검증·유효성 확인은 목적·방법·시점 비교표와 "Built it right vs Built the right thing"의 구분이 핵심이다.

    • 결론 예: "설계 검토·검증·유효성 확인을 개발 관문과 연동하고 결과를 PLM에 기록해, 설계 품질 문제를 양산 전에 차단해야 한다."

    7.2.7 창의적 설계 기법(TRIZ·Pugh·디자인 사고)¶

    TRIZ (82·100·121회)¶

    개념: 러시아의 알츠슐러(G. Altshuller)가 수십만 건의 특허를 분석해, 발명 문제를 해결하는 보편적 원리와 패턴을 정리한 창의적 문제해결 이론이다. 시행착오가 아니라 모순을 해결하는 체계적 방법이다.

    핵심 개념

    • 모순: 기술적 모순(한 특성을 좋게 하면 다른 특성이 나빠짐) / 물리적 모순(한 특성이 서로 반대인 두 상태를 동시에 가져야 함)
    • 40가지 발명 원리와 기술적 모순을 연결한 모순 행렬(39개 기술 특성 × 39개 기술 특성)
    • 이상적 최종 결과(IFR), 자원 활용, 기술 시스템 진화의 법칙, 물질-장 분석

    물리적 모순의 4가지 분리 원리 (100회)

    분리 원리 내용 적용 예
    시간에 의한 분리 서로 반대인 요구를 다른 시간에 충족 이착륙 때만 펼치는 비행기 바퀴
    공간에 의한 분리 서로 다른 장소(부위)에서 충족 다초점 안경(위는 원거리, 아래는 근거리)
    조건에 의한 분리 조건에 따라 성질이 바뀌게 함 온도에 따라 색이 변하는 소재
    전체와 부분에 의한 분리 전체와 부분이 서로 다른 성질을 가짐 자전거 체인(부분은 단단, 전체는 유연)

    진행 절차 (121회): ① 문제 정의(기능·문제점 분석) → ② 모순 정의(기술적·물리적) → ③ 해결 도구 적용(모순 행렬·발명 원리·분리 원리) → ④ 해결안 도출 → ⑤ 평가·구체화

    적용 분야: 제품·공정 설계, 품질 문제 해결, 원가 절감, 특허 회피·신기술 개발, 경영·서비스 문제

    기술적 모순 적용 예: 용기의 강도를 높이려면 두께(무게)가 늘어나는 모순 → 모순 행렬에서 "강도 vs 무게" 칸의 발명 원리를 찾아 복합 재료(원리 40), 곡면화(원리 14) 등을 적용 — 리브·곡면 구조로 얇아도 강한 용기 설계(원리 번호는 교재 확인 필요)

    구분 브레인스토밍 등 심리적 기법 TRIZ
    접근 자유 연상, 시행착오 특허에서 도출한 법칙·원리 적용
    해결 방식 타협(최적점 탐색) 모순 자체를 제거
    재현성 개인 역량에 의존 체계적 절차(ARIZ)로 재현 가능

    디자인 사고(Design Thinking) (112회)¶

    사용자에 대한 공감에서 출발해 문제를 재정의하고, 빠른 시제품과 시험을 반복해 혁신적 해결책을 찾는 인간 중심의 문제해결 방법이다.

    5단계: ① 공감(Empathize) → ② 문제 정의(Define) → ③ 아이디어 발상(Ideate) → ④ 시제품(Prototype) → ⑤ 테스트(Test) — 반복 (IDEO와 스탠퍼드 d.school이 확산시킨 모델)

    특징: 인간(사용자) 중심, 발산과 수렴의 반복, 빠른 실패와 학습, 다학제 협업 — 제조 현장에서는 작업자 관점의 공정·작업대 개선, 서비스 설계에 활용한다.

    Pugh Matrix와 Must-Want Matrix (121회)¶

    제품 재료 선택 사례(경량 하우징 재료 선택)

    ① Must-Want 방법(Kepner-Tregoe): 먼저 Must(필수) 조건으로 대안을 걸러낸 뒤, Want(희망) 조건에 가중치를 주어 점수가 가장 높은 대안을 선택한다.

    Must: 단가 기준 이내 충족 충족 충족 탈락
    Want: 경량성 (가중치 5) 8 → 40 3 → 15 9 → 45 –
    Want: 강성 (가중치 3) 7 → 21 9 → 27 5 → 15 –

    ② Pugh Matrix: 기준안(Datum, 예: 현행 강철)과 비교해 각 대안을 기준별로 더 좋음(+), 같음(S), 더 나쁨(−)으로 평가하고 합산한다. 점수가 높은 대안을 고르거나, 대안들의 장점을 결합해 새 개념을 만든다.

    답안 작성 포인트

    • TRIZ는 창시 배경(특허 분석) → 모순 개념 → 40가지 발명 원리·분리 원리 → 절차 → 적용 분야로 쓴다.
    • Pugh·Must-Want는 문제에서 준 사례(재료 선택)로 평가 표를 직접 작성하는 것이 핵심이다.
    • 결론 예: "TRIZ는 타협이 아닌 모순 해결로 혁신 해를 얻는 도구이므로, 설계 FMEA·QFD에서 드러난 상충 문제에 연계 적용하고 최근에는 AI 특허 분석과 결합해 활용도를 높일 수 있다."

    7.2.8 제품 데이터·수명주기관리(PDM·PLM·BOM)¶

    PDM과 PLM (65·139회)¶

    구분 PDM(Product Data Management) PLM(Product Lifecycle Management)
    정의 도면·BOM·사양·설계 변경 이력 등 제품 데이터를 통합 관리하는 시스템 제품의 기획·설계부터 생산·서비스·폐기까지 수명주기 전체의 정보와 프로세스를 관리하는 전략·시스템
    범위 주로 설계 부서 전사·협력사(공급망)
    기능 문서·버전 관리, BOM 관리, 설계 변경 관리, 워크플로 PDM 기능 + 협업, 프로젝트·포트폴리오, 품질·규제 준수, 서비스 정보

    PLM의 중요 기능 (139회)

    1. 제품 데이터·BOM 관리: 설계 데이터와 BOM을 단일 정보원으로 관리
    2. 설계 변경(ECO)·형상 관리: 변경 요청–검토–승인–반영의 워크플로와 이력 추적
    3. 협업·개발 프로세스 관리: 부서·협력사 간 실시간 정보 공유, 개발 일정·관문(Gate) 관리

    설계 BOM과 제조 BOM (133회)¶

    구분 설계 BOM(E-BOM) 제조 BOM(M-BOM)
    관점 설계(기능) 관점 — 제품을 이루는 부품 구조 제조(조립 순서) 관점 — 실제 생산 공정에 맞춘 구조
    내용 부품과 사양, 도면 번호 공정별 소요 자재, 반제품(중간 조립품), 포장재·소모품
    관리 부서 설계(연구개발) 생산기술·생산관리
    활용 설계 검토, 원가 견적 MRP 입력, 작업 지시, 원가 계산

    E-BOM을 공정에 맞게 변환한 것이 M-BOM이며, PLM과 ERP의 연계로 두 BOM의 일관성을 유지하는 것이 중요하다.

    BOM의 흐름: 설계 BOM(PLM) → 제조 BOM(PLM·ERP, MRP 입력 — 2.4.5) → 서비스 BOM(A/S 부품·정비 단위). 설계 변경(ECO)이 M-BOM·작업 표준·재고에 누락 없이 반영되지 않으면 오조립·불용 재고가 생긴다.

    PLM의 확장: 디지털 스레드와 디지털 제품 여권¶

    • 디지털 스레드: PLM(설계)–ERP(계획)–MES(제조)–보전 데이터를 끊김 없이 연결해, 설계 변경의 영향과 현장 품질 데이터를 양방향으로 추적한다(7.5.2).
    • 디지털 제품 여권(DPP): EU 에코디자인 규정(ESPR)·배터리 규정에 따라 제품의 소재·탄소발자국·수리·재활용 정보를 디지털로 제공하는 제도 — 이 정보의 원천이 PLM의 제품 데이터이므로 PLM이 규제 대응 인프라가 되고 있다(7.5.1, 적용 품목·시기는 최신 자료 확인 필요).

    답안 작성 포인트

    • PDM과 PLM은 범위의 차이(설계 데이터 vs 수명주기 전체)로 비교하고, 설계 BOM과 제조 BOM은 관점과 활용의 차이로 비교한다.
    • 의견으로 E-BOM ↔ M-BOM 불일치 문제와 ECO 연계, 디지털 스레드·DPP 같은 최신 확장을 한 줄 덧붙인다.
    관련 기출 3문항 (65회, 133회, 139회)
    • 제65회(2001) 1교시 9번 · 10점
      PDM(Product Data Management)
    • 제133회(2024) 1교시 13번 · 10점
      설계 BOM(Bill of Material)과 제조 BOM
    • 제139회(2026) 1교시 13번 · 10점
      PLM(Products Lifecycle Management)의 중요기능을 3가지만 설명하시오.

    7.2.9 기타 설계 기법(유니버설 디자인·역설계)¶

    유니버설 디자인 (85회)¶

    정의: 연령·성별·장애 여부·국적과 관계없이 누구나 쉽고 편리하게 사용할 수 있도록 처음부터 설계하는 것이다(R. Mace).

    7원칙: ① 공평한 사용 ② 사용의 유연성 ③ 간단하고 직관적인 사용 ④ 인지하기 쉬운 정보 ⑤ 오류에 대한 포용력 ⑥ 적은 신체적 노력 ⑦ 접근과 사용에 알맞은 크기와 공간

    대상 분야: 생활용품·가전(큰 버튼, 음성 안내), 건축·공공 환경(경사로, 자동문), 교통(저상 버스), 정보·서비스(웹 접근성, 키오스크), 산업 현장(작업대 높이 조절, 시각 표시)

    역설계(Reverse Engineering) (115회)¶

    정의: 완성된 제품을 분해·측정·분석해 설계 정보(형상·구조·작동 원리)를 거꾸로 추출하는 기술이다. 3D 스캐너로 형상을 측정하고 CAD 모델을 다시 만든다.

    절차: ① 대상 분해·분석 → ② 3D 스캐닝(접촉식 CMM·비접촉식 레이저/광학)으로 점군(Point Cloud) 데이터 획득 → ③ 데이터 정리(노이즈 제거·정렬)와 폴리곤(메시) 생성 → ④ CAD 모델 재구성 → ⑤ 검증(원본과 편차 비교) → 3D 프린팅·가공으로 재생산

    용도: 도면이 없는 단종 부품·금형의 복원, 경쟁 제품 분석(벤치마킹), 시제품과 설계 데이터의 비교 검사, 성능 개선 설계의 출발점, 노후 설비의 디지털 트윈 모델 구축

    유의점: 특허·디자인권·영업비밀 등 지식재산권 침해에 주의해야 한다.

    답안 작성 포인트

    • 유니버설 디자인은 정의 → 7원칙 → 대상 분야로, 역설계는 정의 → 절차(측정·모델링) → 용도 → 유의점으로 쓴다.

    답안 작성 예시¶

    25점 예시: 제130회 4교시 5번 — PLC 단계별 그림 설명과 제품설계 과정(예비설계·최종설계)

    1. 개요

    • 제품은 수명주기에 따라 전략이 달라지고, 원가·품질의 대부분이 설계 단계에서 결정되므로 PLC와 설계 과정을 연계해 관리해야 함

    2. 본론

    • (1) PLC: [그림] 도입–성장–성숙–쇠퇴의 매출·이익 곡선(1.5.2) + [표] 단계별 특징·생산 전략(공정 유연성 → 대량화 → 원가 절감 → 철수/재활성화)
    • (2) 신제품 개발 흐름: [그림] 아이디어 창출 → … → 상업화 흐름도에서 예비·최종 설계의 위치 표시
    • (3) 예비 설계: 개념 대안 비교(Pugh Matrix), 기본 구조·핵심 기능 결정, 타당성 재검토
    • (4) 최종 설계: 기능 설계 → 형태 설계 → 생산 설계(DFM·표준 부품·공차) → 시제품 시험 → 설계 확정
    • (5) 단계별 활용 기법 연결: QFD(예비) → DFM·VE·FMEA(최종) → 설계 검토·검증(관문)

    3. 결론(기술사 의견)

    • PLC가 짧아지는 환경에서는 Stage-Gate + 동시공학 + PLM·디지털 트윈 기반 가상 개발로 개발 기간을 줄이고, 성숙기 원가 경쟁을 설계 단계에서 준비해야 함

    25점 예시: 제136회 2교시 4번 — 모듈화의 목적 3가지, QDFRC 관점 장점, Q·C·기타 관점 단점

    1. 개요

    • 모듈러 설계 정의(표준 인터페이스를 가진 독립 기능 단위의 조합) + 배경(다양성 증가 vs 원가 압박, 대량맞춤)

    2. 본론

    • (1) 목적 3가지: 대량맞춤 대응, 공용화로 원가 절감, 병렬 개발·생산으로 기간 단축
    • (2) 장점: [표] 문제가 지정한 Q·D·F·R·C를 표의 행으로 그대로 사용
    • (3) 단점: [표] Q(인터페이스 문제·전체 최적 미달), C(초기 투자·과잉 사양), 기타(차별성 약화·모방 용이·혁신 제약)
    • (4) 차별화: [표] 모듈형 vs 통합형 아키텍처 비교, VRP(고정과 변동·편성의 조합) 연결

    3. 결론(기술사 의견)

    • 단점 보완책 제시: 핵심 차별 모듈은 내재화, 인터페이스 표준 관리, 플랫폼 로드맵(MGPP)으로 아키텍처 고착 방지 — "외부 다양성은 넓히고 내부 다양성은 줄인다"
